# 참여형 계획 대화 진행 기능

## 기존 흐름에 통합

별도 에이전트/챗봇/데이터베이스/분류용 LLM 호출을 만들지 않았습니다. 기존 `/api/chat`, 연구·사례 답변, 공간 도구, 단계 요약 및 관리자 보고서의 호출을 재사용합니다. 모델 ID, OpenAlex 검색, 근거 ID 연결, GIS 계산, 이미지 입력·저장 API는 유지합니다.

`lib/facilitation.ts`는 공통 진행 지침과 가벼운 후속 질문 정책을 제공합니다. 질문에 먼저 답하고, 실제로 도움이 될 때만 한 개의 후속 질문을 허용합니다. 단순 사실·답만 요청·대화 중단·짧은 확인에는 질문을 억제합니다. 모호한 우려는 해결책/고정 선택지를 강요하기 전에 하나의 열린 질문으로 구체화합니다.

일반 LLM 응답은 기존 한 번의 답변 호출에 지침을 포함합니다. 모델의 자유문장을 임의로 잘라 근거/원문을 훼손하지 않습니다. 실제 모델이 항상 정책을 준수한다고 보장하는 별도 검열기는 아닙니다. 공간 도구의 선택적 성찰 질문은 검증된 결과와 참여자가 실제로 표현한 우려가 있을 때만 덧붙이며 추가 모델 호출은 없습니다. 장소 중복 선택/도구 실패에 성찰 질문을 붙이지 않습니다.

## 단계별 행동

1. 문제 정의: 경험, 상황, 장소, 기대와 필요를 이해합니다. 우려가 충분히 이해되기 전에 해결책을 정하지 않습니다.
2. 자료 분석: 실제 자료·공간 계산을 먼저 설명하고 경험과 비교하며 자료 범위를 밝힙니다. 불완전한 시설 검색으로 위험/수요 부족/재개발 필요를 단정하지 않습니다.
3. 계획안 만들기: 참여자 아이디어와 명시한 선호를 보존하고 대안을 탐색합니다. 일반 논의는 기존 ChatGPT 대화로, 계획안 생성·이미지 수정 등 명시적 실행 요청은 기존 이미지 생성 경로로 보냅니다. 기존 단일 추천 질문도 생성 경로를 사용합니다.
4. 계획안 평가: 장단점, 이해관계자별 영향과 상충을 비교하되 특정 선택으로 유도하지 않습니다.
5. 최종안 결정: 우선순위와 이유, 소수 의견, 합의하지 못한 점과 가능한 절충을 보존합니다. 결정을 대신 내리지 않습니다.

확인한 근거, 참여자 발언, AI 해석/제안, 남은 질문을 구분합니다. AI 제안을 참여자 선호로 돌리거나 짧은 ‘네’/침묵을 합의로 취급하지 않도록 일반 대화·근거 답변·개인 요약·관리자 보고 지침에 반영했습니다. 이미지 생성에는 참여자 선호를 임의로 바꾸지 않는 지침만 보완했으며 대화 질문을 이미지 프롬프트에 삽입하지 않습니다.

## 대화 맥락

기존 단계별 대화 문서와 현재 요청의 bounded history를 재사용합니다. 명시적인 후속 질문 거절/재허용과 이미 제시한 공간 성찰 질문은 같은 단계의 저장 로그에서도 확인하므로 최근 LLM 대화 창 밖으로 밀려나도 반복을 줄입니다. 별도 장기기억 컬렉션은 없습니다.

일반 응답 맥락은 기존 최근 12개 메시지/16,000자 제한을 유지합니다. 단계 종료 요약은 화자를 보존한 초기·최근 대화를 최대 60개 메시지/48,000자로 사용하고 누락 여부를 모델에 전달합니다. 서버에 저장된 해당 사용자·사업·단계 로그가 우선이며, 오래된 화자 없는 문장 목록을 참여자 의견으로 추측하지 않습니다. 긴 대화의 모든 중간 세부사항을 무제한 기억하지는 않습니다.

## 단계 요약 검토와 개인정보

기존 단계 완료 확인 뒤 기존 요약 API가 한 번 초안을 만들고, **저장·완료 전에** 참여자가 내용을 수정/확인합니다. 요약은 다섯 가지 짧은 항목(참여자 관심, 관련 근거, 참여자 아이디어, 남은 질문, 다음 단계 검토)으로 작성하도록 지시합니다. 정보가 없으면 채워 넣지 않으며, 요약 편집은 12,000자 이내입니다.

취소하면 단계를 완료하거나 새 초안을 저장하지 않습니다. 확인하면 비공개 개인 요약을 기존 소유자 전용 프로젝트 네임스페이스에 저장합니다:

`users_{projectId}/{uid}.confirmedStageSummaries.{stageId} = {text, confirmedAt}`

이 map을 사용해 대화 로그 전체를 다시 읽지 않고 본인의 검토 요약을 복원합니다. 같은 프로젝트라도 다른 참여자/관리자의 일반 클라이언트로는 읽지 못하는 기존 소유자 규칙을 사용합니다. 새로운 컬렉션이나 보안 규칙 변경은 없습니다.

기존 `ppssWorkspaceSummaries_{projectId}/{uid}`에는 단계 완료 상태를 유지합니다. 현재 검토 요약은 기본적으로 이 공유 문서에 넣지 않습니다. **‘프로젝트 참여자와 공동 보고서에도 공유’**를 사용자가 선택했을 때만 해당 문장을 복사합니다. 기존에 공유된 요약은 자동 삭제하지 않습니다. 공개 overallSummary를 만들 때 새로운 비공개 요약을 섞지 않습니다. 공동 보고서에는 공유된 기여만 사용하며 공개하지 않은 의견/침묵을 합의로 간주하지 않습니다.

완료 단계의 대화창에서 본인의 검토 요약을 읽을 수 있습니다. 기존 완료/관리자 잠금 규칙과 재개방 흐름은 유지합니다. 이후 단계의 기존 `loadProjectContext`는 같은 사용자의 확인 요약을 우선해서 읽습니다. ‘확인’은 참여자의 뜻이 맞다는 확인이며 공간 사실을 독립적으로 검증했다는 의미가 아닙니다. 앞선 자료 분석의 개인 기록도 같은 사용자의 맥락으로만 유지됩니다.

## 수정 파일

- 공통 지침/정책/화자 있는 요약 맥락: `lib/facilitation.ts`
- 일반 대화: `pages/api/chat.ts`
- 사례/논문 답변: `lib/research/answer.ts`, `lib/research/evidence.ts`, `pages/api/research/answer.ts`
- 공간 도구 연결: `pages/api/spatial/query.ts`, `lib/spatial/geo-query.ts`, `lib/spatial/use-geo.ts`
- 설계 입력 선호 보존: `pages/api/generate-alternative.ts`
- 개인/공동 요약 지침: `pages/api/workspace-summary.ts`, `pages/api/admin/executive-summary.ts`
- 비공개 요약과 다음 단계 맥락: `lib/firebase.ts`, `lib/project-context-server.ts`
- 기존 대화/이미지 실행 분기, 검토 dialog, 완료 상태: `pages/workspace/index.tsx`, `lib/i18n.tsx`
- 검증: `tests/facilitation.test.mjs`, `tests/spatial-datasets.test.mjs`, 기존 테스트 실행 스크립트

## 검증과 제한

자동 테스트는 사실 질문, 모호한 우려, 실제 도구 값 뒤의 선택적 질문, 경험/반대/상충된 이해관계 지침, 대화 중단과 재허용, 반복 억제, 기존 단일 모델 호출, 화자 구분, 비공개 요약의 후속 단계 전달을 검사합니다. Firestore 에뮬레이터에서 소유자 전용 저장·조회와 다른 사용자의 접근 차단을 검증합니다.

브라우저에서는 기존 대화/이력, 요약 검토 취소, 수정 후 비공개 완료, 새로고침 복원, 명시적 요약 공유, 모바일 dialog, 3단계 일반 논의와 명시적 이미지 생성 분기를 확인합니다. LLM과 이미지 응답은 테스트 fixture입니다. 실제 공급자의 자연어 품질/지침 준수는 실제 키로 별도 확인해야 하며, 테스트 통과를 실제 모델 행동의 완전한 보장으로 해석하지 않습니다. 운영 배포는 실행하지 않습니다.

최종 실행 결과: 공통/진행 정책 회귀 122개, 업로드·권한·개인 요약 Firestore 검증 31개, 회원/사업 회귀 15개 통과. 프로덕션 빌드(타입 검사 포함) 통과. 신규 진행 모듈 lint 진단 0개, 수정 파일의 새 lint 진단 0개. 경계/UI 브라우저 회귀와 대화/요약/3단계 실행 분기 fixture 검증 모두 통과했습니다. 현재 실행 환경에는 OpenAI·Kakao REST 키가 없어 실제 공급자 응답을 검증하지 않았습니다.
