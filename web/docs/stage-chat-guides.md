# 단계별 채팅 시작 화면

## 변경 전 확인

다섯 계획 단계는 `pages/workspace/index.tsx`의 `renderChatPanel`/`handleSend`를 사용합니다. 문제 정의는 일반 빈 화면, 자료 분석은 한국어 안내, 계획안 평가는 영어 안내를 표시했습니다. 자료 분석·계획안 평가 안내는 실제 대화 앞에 화면에서만 붙였고 Firebase에는 저장하지 않았습니다. 최종안 결정의 기존 안내 설정은 채팅 패널이 렌더링되지 않아 보이지 않았습니다.

계획안 만들기는 별도 자동 생성 효과가 입장 직후 이미지 답변을 생성하고 Firebase에 저장했습니다. 이 효과는 제거했습니다. 이제 첫 질문을 보낼 때 기존 이미지 생성 API를 사용합니다. 초기 생성 입력의 기존 `recentDiscussion`에 첫 질문을 포함하고, 성공 시 기존 `alternativesInitialized` 요약 필드를 유지합니다. 이전에 저장된 자동 이미지 답변은 삭제하거나 필터링하지 않습니다.

## 공유 구조와 전송

- `lib/stage-chat-guides.ts`: 다섯 단계의 제목·설명과 단계·참여자 유형별 추천 질문 3개. 요청된 한국어 문구와 기존 언어 선택에 맞춘 영어·중국어 설정을 제공합니다.
- `components/chat/StageChatEmptyState.tsx`: 기존 말풍선 아이콘과 색상을 재사용하는 가로 Chip을 표시합니다. 잠금/전송 중에는 비활성화합니다.
- `pages/workspace/index.tsx`: 해당 UID/사업/단계의 대화 조회가 끝나고 기록이 비었을 때만 안내를 표시합니다. 조회 중이나 기존 대화가 있을 때는 안내를 표시하지 않습니다. 최종안 결정의 기존 두 결과 영역 아래에도 같은 채팅 패널을 표시합니다.

추천 Chip을 선택하면 화면용 `label` 대신 전체 `prompt`가 입력창에 들어갑니다. 사용자가 전송하거나 Enter를 눌렀을 때 기존 `handleSend`의 메시지 저장·API 요청·오류 처리를 사용합니다. 별도 전송 구현이나 API를 추가하지 않았습니다.

채팅 안내는 메시지 배열에 들어가지 않으며 저장되지 않습니다. 대화의 Firebase 스키마와 저장 경로는 바뀌지 않습니다. 기존 사용자 대화·이미지·근거 기록은 그대로 복원합니다. 빈 기록을 읽으면 안내가 다시 표시됩니다. 새 대화 삭제 기능은 추가하지 않았습니다. 모델/인증/논문 검색/근거 패널/단계 요약 및 단계 완료 처리는 유지합니다.

## 검증 결과

2026-10-05, 실제 화면 컴포넌트를 사용하는 Chromium 검증:

- 다섯 단계에서 제목·설명·질문 4개를 표시하고, 클릭 한 번으로 사용자 메시지와 기존 요청/답변 흐름으로 전환.
- 같은 버튼을 연속 두 번 눌러도 요청 1회, 사용자 기록 1개와 답변 1개. 새로고침하면 안내 없이 기존 대화를 복원.
- 자료 분석의 사례만/논문만/둘 다/명시적 선택 없는 기본 상태를 유지.
- 실패 시 질문을 유지하고 전송 잠금을 해제. 수동 입력 후 재전송 성공.
- 지연된 과거 대화 조회 중에는 안내를 숨기고, 기존 assistant-only 기록도 변경하지 않음.
- 빈 기록으로 돌아오면 안내 복원. 안내만 보는 동안 저장 요청 없음.
- 1440px 데스크톱/390px 모바일의 다섯 단계에서 읽기와 줄바꿈 확인, 가로 넘침 없음.

브라우저 검증은 Firebase 인증과 AI 응답, 대화 저장 경계에 검증용 구현을 사용했습니다. 운영 로그인/실제 AI 응답을 검증한 것은 아닙니다. 프로젝트 입장은 실제 프로젝트 API와 로컬 Firestore 에뮬레이터를 사용했습니다.

기존 연구·대화 저장·공간 분석 테스트 **32개 통과**. TypeScript 검사와 프로덕션 빌드 통과. 새 안내 컴포넌트/설정 파일은 ESLint 오류 없음. 기존 작업 공간에는 관련 없는 lint 오류가 남아 있으며 수정하지 않았습니다.

변경 파일: 위 세 구현 파일과 이 문서. 프로젝트 참여 저장 변경은 별도 커밋과 `project-membership.md`에 기록합니다.


## 단계·참여자별 시작 질문

질문은 AI가 생성하지 않는 정적 데이터이며, 기존 `stageChatGuide` 함수에서 `suggestedQuestions[locale][stageId][roleId]`를 선택합니다. 기존 내부 ID인 `public`, `business`, `planners`, `government`와 `normalizeRoleId`를 재사용합니다. 작업 공간의 기존 `ppss-role` 참여 역할 상태를 넘기며, 알 수 없는 역할은 시민용 질문으로 표시합니다. 권한 판정이나 로그인 역할 저장 방식은 변경하지 않습니다.

문제 정의·자료 분석·계획안 만들기·평가·최종 결정의 20개 조합에 각각 3개, 한국어 총 60개 질문을 요청 데이터를 기반으로 등록했습니다. 한국어 운영진 질문은 추진·운영·예산·인력 관점에 맞게 조정했습니다. 영어·중국어에도 같은 20개 조합과 자연스러운 번역을 제공합니다. 제목·설명, 질문 위치·아이콘·스타일, 빈 대화에서만 보이는 조건은 유지합니다. 계획안 만들기도 최신 요청에 따라 기존 질문 1개 대신 역할별 3개를 표시합니다.

기존 질문 버튼은 즉시 전송 방식이었지만, 후속 Compact Starter Prompts 요청에 따라 Chip 선택 시 전체 질문을 입력창에 넣는 방식으로 변경했습니다. 실제 전송과 생성 요청인지 논의인지 판단하는 기존 라우팅, AI 프롬프트·후속 질문·저장 API는 유지합니다.


## Compact Starter Prompts

각 질문은 짧은 `label`과 변경하지 않은 전체 `prompt`로 구성합니다. 기존 말풍선 아이콘과 색상을 사용하는 가로 Chip이 공간에 맞춰 줄바꿈합니다. 빈 대화에서는 Chip 3개만 표시하며 큰 안내 제목·설명을 반복하지 않습니다.

대화 이력이 있으면 입력창 위의 ‘추천 질문’ 버튼으로 Chip을 열고 닫습니다. 선택하면 전체 질문을 입력창에 넣고 다시 접습니다. 메시지 전송·단계 이동·사업/사용자 전환 때 펼침 상태를 초기화하며, 새로고침 뒤에는 해당 단계의 실제 이력 유무로 시작 상태를 결정합니다. 펼침 상태는 로컬 UI 상태이며 Firebase에 저장하지 않습니다. 잠금·전송·조회 중의 기존 제약을 따릅니다.


현재 검증: 관련 테스트 149개, 타입 검사, 변경된 설정/Chip/테스트 파일 lint, 프로덕션 빌드 통과. 운영진 표기와 기존 역할 이름의 호환, 단계별 추천 질문 연결을 확인했습니다. Chromium에서 한국어·영어 각각 20개 조합의 label/전체 질문 입력, 첫 전송 후 접기, 다시 열기·선택 후 접기, 단계 이동·새로고침 복원과 기존 메시지 저장을 확인했습니다. 1440/1180/820/390px에서 입력창 표시와 패널 크기, 긴 대화 읽기 위치를 확인했고 태블릿 터치 선택도 확인했습니다. Firebase/AI 응답 경계는 로컬 테스트 구현을 사용했으며 실제 iPad Safari·운영 Firebase·실모델 답변 품질 검증은 아닙니다.

한국어 참여자 유형은 운영진으로 표시하며, 기존 내부 `government` ID를 그대로 사용합니다. 예전 `공무원`·`정부` 표기도 같은 참여 역할로 인식합니다. 영어·중국어 표시와 기존 관리자 권한 지정 방식은 유지합니다.
