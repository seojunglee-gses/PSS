# 관리자 참여자별 연구자료 내보내기

설정 → 관리자 설정 → **참여자별 연구자료 다운로드**에서 참여자를 선택하거나 전체 참여자를 선택한다. 전체 ZIP은 `001-참여자ID/`, `002-참여자ID/`처럼 참여자별 폴더로 나뉜다. 개별 선택 시 해당 참여자 폴더만 받는다.

## 포함하는 자료

- `participant.json`: 사업/사용자 식별자, 표시 ID, 내보낸 시각.
- `conversation.json`: 1~5단계 원문 문서, 기존 통합 저장본, soft reset 이전 보관 문서. 문서 ID와 경로 및 원문 필드를 유지한다.
- `conversation.csv`: 원문 경로, 단계, 보관 여부, 메시지 위치/ID, 세션 ID, 시각, 발화자, 발언, 이미지 ID를 펼친 열람용 파일. JSON 원문이 기준이다.
- `summaries.json`: 기존 사용자별 확인 요약 및 workspace 요약·완료 상태. 재생성하지 않는다.
- `evaluations.json`, `rankings.csv`: 기존 평가 기록 전체와 순위 및 제출 이미지 연결. 최신 기록만 고르거나 순위를 재집계하지 않는다.
- `images.json`, `images/`: 생성·수정 이미지 버전 전체, 원본 바이너리, 원본 프롬프트(`note`), 모델 설정, 부모/루트 이미지 ID, 수정 요청 등 저장된 메타데이터.
- `activity-logs.json`: 원문에 저장된 명시적 활동 이벤트(사례/논문/지도 등). 사용자 발언으로 변환하지 않는다.
- `image-downloads.json`: 이미지별 바이너리 다운로드 성공/실패. 일부 원본을 받을 수 없어도 JSON·CSV·프롬프트 및 기존 링크는 ZIP에 남기고 화면에 부분 실패를 알린다.
- `README.txt`: 저장 형식과 이용 시 주의점.

## 권한과 데이터 보존

서버의 기존 사업 관리자 판별과 참여자 제외 기준을 사용한다. 일반 참여자와 다른 사업의 관리자는 받을 수 없다. 테스트 관리자와 사업/시스템 관리자는 참여자 대상에서 제외한다. 완료 여부와 무관하게 저장된 기록이 있는 참여자를 찾으며, 단계 하위 문서만 존재하는 사용자도 포함한다.

읽기 전용 GET API는 인증 토큰을 검사하며 비공개 `no-store` 응답을 사용한다. 이미지 요청마다 사업·사용자 소유 관계를 확인하고, 허용된 현재 사업의 Storage 경로만 읽는다. 외부 임의 URL은 요청하지 않는다. DB/Storage 쓰기·마이그레이션·요약 및 AI 호출은 없다.

## 성능과 제한

참여자와 이미지를 순차로 읽고 브라우저에서 기존 `fflate`로 ZIP을 구성한다. 중복 클릭을 막고 화면/계정/사업 전환 시 요청을 중단한다. ZIP 입력 합계는 브라우저 메모리를 고려해 150MB, 원본 이미지는 파일당 20MB, 전체 작업은 10분으로 제한한다. 큰 전체 자료는 참여자를 나눠 받는다. 추가 서버 임시 파일이나 내보내기 저장본은 만들지 않는다.

원본과 기존 저장 형식을 모두 보존하므로 동일 발언이 여러 문서에 중복 존재할 수 있다. 분석 시 단순 합산하지 않는다. 여러 문서는 순차 읽기이므로 전체가 동일 시점의 스냅샷은 아니다. 실제 워크숍 진행 중인 계정은 이후에 기록이 추가될 수 있다. 기존에 수집하지 않은 클릭/체류시간/로그인 이력은 복원하지 않는다. 참여자 식별정보와 원문은 익명화되지 않는다.

## 검증

`bash web/tests/run-participant-export-tests.sh`는 모의 Firestore/Auth/Storage만 사용해 권한, 미완료 계정 탐색, 참여자/사업 격리, 원문 불변성, 전체 버전 및 prompt 연결, 이미지 경로 제한, 파일 구성과 CSV 수식 방어를 확인한다. 운영 DB와 실제 연구 자료는 사용하지 않는다.
