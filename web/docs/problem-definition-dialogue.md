# 문제 정의: 성찰과 비판적 사고를 돕는 대화

## 원인과 변경 범위

이전 문제 정의 지침은 OPTIONAL/CLARIFY일 때 반드시 질문 하나로 끝내도록 했고, 장소·시간·상황 등의 빈 정보를 찾는 데 초점을 두었습니다. 다른 단계와 달리 직전 AI 질문 뒤에도 계속 질문하도록 예외를 두어, 이미 충분히 설명한 주제도 인터뷰가 이어질 수 있었습니다.

`lib/facilitation.ts`의 문제 정의 분기에만 새 지침을 적용합니다. 공통 `/api/chat` 프롬프트, 모델 선택, 프로젝트 자료, 최근 12개 메시지/16,000자 맥락, Firestore 저장과 단계 완료 보고서 흐름은 유지합니다. 대화 중의 잠정 문제 정의는 자동 저장 보고서나 단계 완료 처리가 아닙니다.

## 능동적인 탐색 보강

짧은 동의나 질문을 쉬는 차례에도 대화를 자동으로 끝내지 않고, 맥락에 맞는 고려사항·아이디어·가상의 이해관계자 관점 하나를 제안할 수 있도록 보강했습니다. 기본 응답은 1~3문장이며, 질문 없이도 대화를 이어갈 실마리를 제공할 수 있습니다. 감사·중단·직접 답변·명시적 요약 요청은 그대로 존중합니다. 매 차례 요약하거나 여러 아이디어를 나열하지 않습니다.

## 바뀐 프롬프트

실제 영어 지침은 `problemDefinitionInstructions`와 `stages.problem`에 있습니다. 핵심은 다음과 같습니다.

- 사용자의 요청에 먼저 답하며, 의견·경험에는 단순 반복보다 의미에 대한 짧은 해석을 제공합니다.
- 문제·원인에 대한 해석은 가설입니다. 사용자 발언, 사업 자료로 확인한 사실, AI 해석을 구분합니다.
- INTERPRET / REFLECT / REFRAME / SYNTHESIZE / PRIORITIZE 중 실제로 필요한 기능을 선택합니다. 고정 순환이나 응답별 필수 소제목으로 사용하지 않습니다.
- 질문하기 전에 그 답이 현재 문제 정의를 실질적으로 발전시키는지 판단합니다. 질문은 최대 하나이며, 하지 않아도 됩니다.
- 구체적인 장소·시간보다 판단 근거, 가치, 우선순위, 다른 이해관계자 관점과 기대하는 변화에 집중합니다. 불필요한 개인정보나 민감한 경험은 요구하지 않습니다.
- 대안적 관점은 유용할 때 하나만 잠정적으로 제안합니다. 반박하거나 AI의 선호로 유도하지 않습니다.
- 충분히 설명되었거나 정리를 요청하면 핵심 문제 / 배경·맥락 / 가능한 원인 / 이해관계자 / 사용자 가치 / 추가 검증 가설을 짧게 종합합니다. 모르는 항목은 확인되지 않았다고 표시합니다.
- 사용자 수정은 이전 AI 가설보다 우선합니다. 짧은 동의나 침묵은 합의가 아니며, 개인 의견을 지역사회 전체의 의견으로 확대하지 않습니다.

### 가벼운 질문 정책

별도 분류 API 호출은 없습니다. 기존 질문 중단·재허용·사실 질문·짧은 확인 정책을 유지하며, 문제 정의에만 다음 제한을 추가합니다.

1. 명시적인 정리 요청에는 후속 질문을 하지 않습니다.
2. 최근 AI 답변 두 개가 모두 질문으로 끝났다면, 다음 답변은 질문을 쉬되 유용한 연결이나 선택적인 아이디어로 대화를 이어갈 수 있습니다. 사용자가 명시적으로 질문을 요청하면 재허용합니다.
3. 두 번의 질문이 있었다는 이유만으로 충분한 근거가 모였거나 사용자가 동의했다고 간주하지 않습니다.

이 정책은 프롬프트 지시이며, 생성된 자연어를 사후에 자르거나 바꾸는 검열기는 아닙니다.

## A–D 검토용 기대 대화

**아래 예시는 작성한 기대 응답입니다. 실제 모델 출력이나 실측 품질 평가 결과가 아닙니다.** 사업 사실이나 사용자의 가치를 새로 가정하지 않는 방식으로 검토합니다. 예시 문장을 프로덕션의 고정 템플릿으로 삽입하지 않았습니다.

### A. 주민이 모일 공간

사용자: 우리 동네는 주민들이 모일 공간이 부족해요.

AI 기대 응답: 모일 장소가 부족하다는 말씀은 이웃과 관계를 맺을 기회가 충분하지 않다는 문제와 연결될 수도 있겠습니다. 공간이 더 생겼을 때 주민들의 생활에서 어떤 변화가 가장 중요하다고 보시나요?

사용자: 행사가 가끔 있는 것보다 평소에 이웃과 알고 지낼 수 있는 관계가 중요해요.

AI 기대 응답: 큰 행사보다 일상적으로 관계를 이어갈 기회를 중요하게 보시는군요. 그렇다면 새 공간의 수뿐 아니라, 기존 공간을 지속해서 이용할 수 있는지도 살펴볼 만한 가설입니다.

사용자: 새 건물을 원하는 건 아니고 기존 주민센터를 저녁에도 이용할 수 있으면 좋겠어요. 핵심 문제를 정리해줘.

AI 기대 응답:

- **핵심 문제:** 일상적으로 이웃과 관계를 이어갈 공간을 이용할 기회가 부족하다는 우려입니다.
- **배경·맥락:** 참여자는 새 시설보다 기존 주민센터의 저녁 이용을 제안했습니다. 실제 운영 시간은 확인되지 않았습니다.
- **가능한 원인:** 이용 시간과 주민 생활시간의 불일치가 원인일 수 있지만 아직 가설입니다.
- **이해관계자:** 주민센터 이용 주민과 운영 주체가 관련될 수 있으며, 각각의 입장은 확인이 필요합니다.
- **사용자 가치:** 참여자가 직접 강조한 가치는 일상적인 이웃 관계의 지속입니다.
- **추가 검증 가설:** 저녁 이용 확대가 지속적인 교류를 늘릴지 확인해야 합니다.

이 정리는 잠정안이며, 다르게 이해된 부분은 수정할 수 있습니다.

### B. 노인의 생활 불편

사용자: 이 지역은 노인들이 살기 불편한 것 같아요.

AI 기대 응답: 어르신이 일상생활을 원하는 방식으로 이어가기 어려울 수 있다는 우려로 읽힙니다. 불편이 줄었다고 판단하려면 어떤 변화가 가장 중요할까요?

사용자: 불편해도 다른 사람 도움 없이 장을 보고 외출할 수 있는 게 중요하다고 생각해요.

AI 기대 응답: 불편을 없애는 것과 함께 스스로 생활할 수 있는 선택권을 중요하게 보시는군요. 시설의 수뿐 아니라 실제로 이용할 수 있는 조건을 살펴보는 관점도 도움이 되겠습니다.

수렴 시 기대 방향: **어르신의 독립적인 일상 활동을 가능하게 하는 이용 조건에 대한 우려**로 잠정 정리합니다. 실제 이동 장벽·시설 부족·다른 노인 주민의 선호를 확인된 사실로 만들지 않습니다. 이미 설명한 자립의 의미를 다시 묻지 않고, 추가 근거가 없다면 가능한 원인과 검증 필요 사항을 구분합니다.

### C. 청년 이탈

사용자: 청년들이 이 동네를 떠나는 게 가장 큰 문제라고 생각해요.

AI 기대 응답: 청년 이탈을 지역이 지속되는 데 중요한 문제로 보고 계시는군요. 청년이 떠나는 현상에서 특히 우려하시는 변화는 무엇인가요?

사용자: 모두 계속 살아야 한다는 건 아니지만 살고 싶은 사람도 주거비 때문에 나가는 것이 걱정이에요.

AI 기대 응답: 모든 청년을 붙잡기보다, 남고 싶은 사람에게 거주 선택권이 있는지를 중요하게 보시는군요. 참여자께서 주거비를 원인으로 말씀하셨지만, 실제 이주 원인은 자료로 따로 확인해야 합니다.

수렴 시 기대 방향: **거주를 희망하는 청년의 주거 선택권이 제한될 수 있다는 우려**로 수정합니다. ‘청년은 무조건 남아야 한다’는 초기 해석을 유지하지 않습니다. 실제 이탈 규모와 주거비의 영향은 검증 전 가설로 남깁니다.

### D. 공원 제안

사용자: 공원을 새로 만드는 게 좋을 것 같아요.

AI 기대 응답: 공원 조성은 생활환경을 바꾸기 위한 하나의 제안으로 볼 수 있겠습니다. 공원을 통해 지금의 생활에서 무엇이 달라지기를 바라시나요?

사용자: 녹지 자체보다는 집 밖에서 돈을 쓰지 않고 쉬거나 이웃을 만날 수 있는 게 중요해요.

AI 기대 응답: 녹지의 양보다 비용 부담 없이 쉬고 만날 수 있는 기회를 중요하게 보시는군요. 새 공원뿐 아니라 기존 공간의 이용 방식도 그 목표에 도움이 될 가능성은 있습니다.

수렴 시 기대 방향: **비용 부담 없이 쉬고 교류할 수 있는 일상 공간의 이용 기회**로 잠정 정리합니다. 공원이 반드시 해답이라고도, 필요 없다고도 단정하지 않습니다. 실제 공간 현황·접근 조건·다른 이해관계자 관점은 확인이 필요합니다.

## 검증 결과와 한계

- 자동 테스트는 A–D 원문 전달, 단일 기존 모델 호출, 문제 정의 전용 지침, 두 번의 연속 질문 뒤 쉬기, 거절/재허용, 사용자 수정과 사업 자료 보존, 여섯 항목 종합 지침을 검사합니다.
- 자료 분석·계획안·평가·최종 단계는 수정 전후 24개 입력/이력 조합에서 프롬프트 문자열과 정책 결과가 동일했습니다.
- 이번 전체 관련 테스트 145개, 타입 검사, 프로덕션 빌드 결과를 PR에 기록합니다.
- 실제 OpenAI 호출을 시도했으나 환경의 인증정보로는 호출이 실패하여 실제 모델 A–D 다회차 대화를 검증하지 못했습니다. 모의 응답을 사용하는 API 테스트 통과를 자연어 품질 검증으로 간주하지 않습니다.
- 긴 대화는 기존 맥락 제한을 유지합니다. 중간에 등장한 모든 가설과 수정을 무제한 기억한다고 보장하지 않습니다.
