# 태블릿 터치와 사이드바

공간 분석의 버튼·선택 상자·레이어/결과 첨부 라벨·결과 삭제는 최소 44px 터치 높이를 사용합니다. 지도 확대/축소/방향 버튼은 터치 포인터에서 44×44px이며 마우스 환경에서는 기존 크기를 유지합니다. 페이지에 한 손가락 지도 이동, 두 손가락 확대/축소, 지도 바깥 페이지 스크롤 안내를 표시합니다.

## Workspace 화면

- 5단계 메뉴는 `flex-wrap: nowrap` 한 줄을 유지합니다. 항목 간격·여백을 줄이고 현재 단계만 조금 넓게 표시합니다. 아주 좁은 화면에서는 메뉴 안에서 가로로 스크롤하며 단계 클릭 동작은 유지합니다.
- 역할·이메일·로그아웃은 44px 높이의 상단 행으로 표시합니다. 다른 페이지의 계정 카드는 변경하지 않습니다.
- 처음에는 전체 Workspace 제목·설명·AI 서비스를 표시합니다. 실제 사용자가 패널을 64px 이상 아래로 스크롤하면 제목과 현재 단계만 남습니다. 위로 돌아오면 다시 펼쳐집니다. 400ms 전환 잠금으로 레이아웃 변경에 따른 반복 전환을 막고, 대화 복원·프로그램 스크롤에는 반응하지 않습니다. 축소 애니메이션은 220ms이며 동작 줄이기 설정을 따릅니다.
- 세로 모드에서 채팅 보기로 전환하면 제목을 축소하고 단계 메뉴를 유지합니다. 왼쪽 자료와 대화 목록은 각각 내부에서 스크롤되며 채팅 입력창은 목록 밖의 하단 영역에 남습니다. 화면 키보드가 열릴 때는 기존 visualViewport 처리와 추가 축소 동작을 유지합니다.

## 사이드바 기준

- Workspace 1280px 미만: 세로·가로 태블릿과 모바일 모두 오버레이 메뉴를 사용합니다. 고정 설정이 저장되어 있어도 본문 폭을 차지하지 않습니다.
- 1280px 이상: 기존 76px 레일, 288px 펼침/고정 패널을 유지합니다. 마우스 hover는 fine pointer에서만 사용합니다.
- 햄버거 한 번 탭으로 열고 같은 버튼을 다시 탭하면 닫습니다. 바깥 탭, 닫기 버튼, 링크 이동, Escape로도 닫습니다. 메뉴를 연 뒤에도 상단 햄버거가 오버레이 위에 남습니다.
- 계정 행 전체는 오버레이 뒤에 두고 햄버거 버튼만 위에 표시합니다. 메뉴가 열리면 역할·이메일·로그아웃은 숨기며, 닫으면 다시 표시합니다. 태블릿에서 계정 행이 사이드바 위를 가로지르던 표시 순서 문제를 수정했습니다.
- 클릭 토글은 hover 표시 상태 대신 명시적인 열림/고정 상태를 기준으로 합니다. 터치/클릭 중복 핸들러를 추가하지 않습니다.
- Workspace 외 페이지의 기존 모바일/데스크톱 표시 기준과 사이드바 고정 저장 형식은 유지합니다.

좌우 패널 전환·분할·비율 조절은 기존 `workspaceLayoutMode`와 너비 제한을 사용합니다. 사업 권한, Firebase, 대화 저장, 공간 계산과 자료 선택은 변경하지 않습니다.

## 검증

Chromium 터치 에뮬레이션에서 820×1180, 1024×1366 세로, 1180×820 가로와 390×844 모바일, 1440×1000 데스크톱을 확인했습니다. 한 줄 단계 메뉴, 열기/재탭 닫기/바깥 탭/Escape, 실제 터치 스크롤에 따른 헤더 축소, 자동 스크롤 제외, 위로 돌아왔을 때 펼침, 단계 이동과 입력창 위치가 통과했습니다. 1180×820에서 헤더 축소 후 작업 패널은 551px에서 623px, 대화 목록은 329px에서 401px로 늘었습니다.

기존 패널 회귀 검사에서도 너비 조절·전환·대화 스크롤 복원·visualViewport 축소 시 입력창 위치를 확인했습니다. 회귀 테스트 82개, TypeScript, 프로덕션 빌드가 통과했고 변경 파일의 새 lint 진단은 없습니다. 브라우저 인증·사업 자료·대화는 테스트 구현을 사용하므로 실물 iPad Safari와 OS 키보드 확인을 대신하지 않습니다.
