# 태블릿 터치와 사이드바

공간 분석의 버튼·선택 상자·레이어/결과 첨부 라벨·결과 삭제는 최소 44px 터치 높이를 사용합니다. 지도 확대/축소/방향 버튼은 터치 포인터에서 44×44px이며 마우스 환경에서는 기존 크기를 유지합니다. 페이지에 한 손가락 지도 이동, 두 손가락 확대/축소, 지도 바깥 페이지 스크롤 안내를 표시합니다.

작업 공간은 1280px 미만에서 지도와 대화를 한 열로 배치합니다. 작은 화면의 고정 입력창은 44px 버튼, 16px 입력 글자와 기기 하단 안전 영역 여백을 사용합니다. 1024~1279px에서는 사이드바 폭을 제외해 입력창이 가려지지 않습니다. 본문 하단에 입력창/선택 자료 표시가 마지막 동작을 덮지 않을 여백을 둡니다. 1280px 이상에서는 기존 두 열 배치를 사용합니다.

1024px 이상에서 사이드바는 기본 76px 아이콘 영역입니다. 펼칠 때 288px 패널이 본문 위에 표시되어 hover만으로 본문 위치가 바뀌지 않습니다.

- 마우스: hover 시 펼치고 벗어나면 접습니다. 클릭으로 열린 상태를 유지할 수도 있습니다.
- 터치: 펼치기 버튼으로 열고 접기 버튼 또는 패널 바깥을 눌러 닫습니다. 터치를 마우스 hover로 취급하지 않습니다.
- 고정: 패널을 고정하면 본문 옆에 공간을 확보합니다. 고정 해제/접기가 가능하며 `ppss-sidebar-pinned`에 브라우저별 표시 설정만 저장합니다.
- 키보드: 펼치기 버튼과 이동 링크를 사용할 수 있습니다. Escape로 접고 펼치기 버튼에 포커스를 돌려줍니다.
- 1024px 미만: 기존 모바일 메뉴를 유지하며 메뉴·닫기 터치 버튼을 키웠습니다.

표시 설정은 새로고침·페이지 이동 뒤 복원되고 다른 탭의 변경도 반영합니다. 저장이 불가능하면 현재 세션에서 고정/해제를 사용할 수 있습니다. 사용자 역할/사업 권한, Firebase 경로, 대화 저장, 공간 계산과 자료 선택 로직은 바꾸지 않습니다.

검증: Chromium의 터치 재현 환경에서 820×1180 세로와 1180×820 가로의 지도 이동·핀치 확대·도형 선택·레이어 전환·영역/버퍼 분석·결과 첨부를 확인했습니다. 주요 공간 컨트롤은 모두 44px 이상이었고 가로 지도 폭은 기존 약 349px에서 약 972px로 늘었습니다. 입력창이 사이드바나 마지막 단계 버튼을 가리지 않는 것도 확인했습니다. 마우스 hover 본문 위치 유지, 키보드, 고정 저장/해제/복원, 바깥 터치로 닫기, 390px 모바일 메뉴 이동도 통과했습니다.

브라우저 인증/사업 자료는 테스트 구현을 사용합니다. 실물 iPad Safari, OS 화면 키보드, 대용량 사업 데이터의 성능을 보장하는 검증은 아닙니다. 지도 제공자 응답은 클라우드 브라우저의 인증서 신뢰 제약 때문에 TLS를 검증하는 curl 경유로 전달합니다.

프로덕션 빌드/TypeScript와 기존 연구·공간·대화 및 새 사이드바 저장 검사 총 43개가 통과했습니다. 선택 파일 ESLint에는 기존 AppShell 역할 로드/SpatialMap ref 처리에서 발생하던 오류 5개가 남아 있습니다. 이번 작업의 새 오류는 없으며 관련 없는 동작은 수정하지 않았습니다. 운영 배포는 실행하지 않았습니다.
