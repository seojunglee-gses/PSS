# Interface localization and case editing

Case Studies opens in reading mode for every role. Project/system managers can use the heading’s Edit control, styled like Problem Definition. Editing reveals case add/delete controls, title/body/image editing and Save/Cancel at the heading; the previous in-content “사례 수정” control is removed. Switching cases preserves drafts. Additions and confirmed deletions are part of the same draft: Save persists the ordered array and stable IDs through the existing project API, while Cancel restores the saved content. Delete confirmation uses a native dialog with localized title, warning and Cancel/Delete buttons.

The audit covers Home/project entry, Workspace’s five stages, Settings, Report, sidebar/account navigation, shared rich-text/image editors, suggested-question labels, source selection, evidence labels, spatial tool controls, dataset management, spatial summaries, map control accessibility labels, confirmation dialogs and error/success notices.

Fixed interface copy uses the existing `web/lib/i18n.tsx` catalogs and `web/lib/research/labels.ts`. Interpolation supports names and counts. Built-in notices and saved spatial summary messages are localized at display time; unknown server/SDK errors use a translated fallback while the original diagnostic stays available to the application. Language changes update map labels without rebuilding the map. New English/Korean catalog entries have matching keys and parameters.

Authored project/case prose, original chat questions/answers, paper titles/abstracts, uploaded filenames, dataset names/attributes, identifiers and technical product names remain original. Only exact built-in starter content is translated for display. Stored project/chat data, source routing, research retrieval, spatial calculations and Firebase schemas are unchanged.

Validation includes catalog/parameter parity, legacy-message interpolation, authored-content preservation, and an AST guard against hardcoded frontend JSX labels. The test compiler uses the app’s strict checking and ESNext/DOM library context for the added client i18n module. Browser checks use real project APIs with the Firestore emulator, fixture authentication/Storage and intercepted spatial data. They do not verify live cloud credentials or physical tablet browsers.

All 85 regression tests passed. Browser checks verified reading-mode defaults, heading editing, multi-case drafts, rich-text save/reload, stable IDs/order, deletion confirmation, Cancel rollback, failed-save draft retention, participant access, live English/Korean switching, localized stage confirmation, English Home/Settings/Report and spatial tools/map controls. Separate touch checks at 820×1180, 1024×1366, 1180×820 and 390×844 verified that opening the sidebar hides the account row, keeps the hamburger usable, and restores account information when closed.
