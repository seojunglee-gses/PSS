# 개인 대화 저장·복원 및 논문 요약 검증

검증일: 2026-10-04. 실제 사용자의 기존 대화 전체를 조회한 감사 결과는 아닙니다.

## 저장과 복원

현재 대화는 Firebase UID, 사업 ID, 단계별로 `users_{projectId}/{uid}/steps/{stepId}` 문서의 `logs` 배열에 저장됩니다. 같은 계정과 같은 사업으로 접속해야 같은 기록을 불러옵니다. 브라우저 저장소만을 이용하는 방식은 아닙니다. 채팅이 있는 단계는 문제 정의, 자료 분석, 계획안 만들기, 계획안 평가입니다. 최종안 결정은 보고서·요약 화면입니다.

자료 분석의 질문, 답변, 출처 선택, 논문 정보, 인용 ID와 링크도 기존 대화 기록에 함께 저장됩니다. 논문 초록 원문은 저장하지 않고 답변과 근거 메타데이터를 보관합니다. 다른 기기에 접속하거나 단계를 다시 열거나 새로고침할 때 복원하며, 다른 기기에서 작성한 내용을 실시간 구독하는 기능은 없습니다.

확인하고 보완한 문제:

- 복원한 대화의 선택적 이미지 필드가 `undefined`인 상태로 저장돼 Firestore가 거부하는 문제를 실제 SDK 입력 검증으로 재현했습니다. 모든 단계의 저장 전에 빈 이미지 필드를 정리합니다.
- 질문·일반 답변 저장을 기다리지 않아 실패를 놓칠 수 있었습니다. 질문 저장 확인 후 AI를 호출하고, 답변 저장도 기다리며 실패를 명시합니다.
- 기존 기록을 읽기 전에 새 대화를 보내거나 이전 조회가 늦게 도착하면 기록을 덮어쓸 수 있었습니다. 복원 완료 전 전송을 막고 취소된 조회 결과를 무시합니다.
- 두 기기의 오래된 대화 배열을 각각 덮어쓰면 한쪽의 새 질문·답변이 사라졌습니다. 같은 문서에 Firestore 트랜잭션으로 양쪽 기록을 합칩니다. 재시도 시 중복을 만들지 않고 원래 논문 근거를 보존합니다.
- 계정·사업 전환 시 대화와 근거 캐시를 비우고, 이전 계정의 진행 중인 요청과 늦게 도착한 개인 요약이 새 계정 화면·분석 맥락에 들어가지 않도록 합니다.

저장 문서 경로와 데이터 필드는 유지했습니다. 저장은 서버 연결과 권한이 유효해야 성공합니다. Firestore 문서 크기 한도(1 MiB)가 적용되는 배열 저장 방식이므로 무제한 보관을 보장하지 않습니다. 현재 사용자의 실제 기록 크기나 과거의 별도 저장 형식 존재 여부는 확인하지 못했습니다.

## 테스트 범위

- TypeScript 검사, 프로덕션 빌드, 연구/API 테스트와 대화 병합 테스트 총 21개 통과.
- 데스크톱과 모바일의 별도 브라우저 컨텍스트에 공통 테스트 저장소를 제공해 4개 채팅 단계의 기존 기록과 새 질문·답변 복원을 확인했습니다. 두 브라우저는 로컬 저장소를 공유하지 않습니다.
- 논문 요약의 출처 선택, 논문 제목과 메타데이터, 정확한 OpenAlex 인용 링크 복원을 확인했습니다.
- 느린 조회, 조회·질문 저장·답변 저장 실패, 계정 전환 중 요청, 개인 요약의 늦은 조회를 검증했습니다.
- 동시 저장 문제는 기존 전체 배열 쓰기를 재현한 테스트 저장소에서 확인했고, 트랜잭션과 동일한 병합 함수를 적용한 뒤 양쪽 질문·답변 보존을 확인했습니다. 실제 Firestore에서 두 로그인 세션으로 트랜잭션을 실행한 검증은 아닙니다.
- 기존 전체 lint 결과는 오류 27개·경고 40개로 유지됩니다.

## 실제 논문 검색과 요약

실제 OpenAlex 호출로 한국어 주민 참여·이주 위험 질문에서 논문 기록 8개와 초록 8개를 가져왔습니다. 짧은 한국어 검색어와 영어 검색어에서도 각각 초록이 있는 기록 8개를 가져왔습니다. 주민 참여, 주민 의견 수렴, 원주민 재정착 등 질문과 관련된 자료를 확인했습니다. 한 한국어 질문의 결과에는 초록 내용이 동일한 중복 기록 두 쌍이 있어 독립적인 연구 수를 단순히 검색 기록 수와 동일하게 보아서는 안 됩니다.

검증 환경에서 OpenAI의 실제 요약 호출은 인증 오류로 실패했습니다. GitHub에 등록된 Production 배포 주소와 기본 프로젝트 별칭의 API는 배포 접근 보호(401)로 호출할 수 없었습니다. 따라서 **운영 환경의 실제 AI 요약 성공, 로그인한 계정의 Firestore 저장, 실제 두 기기 로그인 복원은 아직 확인하지 못했습니다.** 화면 테스트의 AI 응답은 대체 응답이며 실제 요약 성공으로 보고하지 않습니다. 현재 사용 중인 접근 가능한 배포 주소와 로그인 검증 환경, 서버의 유효한 OpenAI 인증 설정으로 최종 확인해야 합니다.

## 개인 대화 접근 권한

계정별 저장 경로가 개인 정보 접근 차단을 보장하지는 않습니다. 저장소의 `web/firestore.rules`에는 모든 경로에 대해 로그인한 사용자의 읽기·쓰기를 허용하는 규칙이 있습니다. 운영에 적용된 규칙은 조회하지 못했습니다. 개인 대화 문서의 접근을 소유 UID에 제한하는 정책을 별도로 검토·배포해야 합니다. 이번 수정은 접근 권한 규칙을 바꾸지 않습니다.
